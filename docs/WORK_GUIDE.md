# Media Insight 테스트 브랜치 작업 지침서

**v1 · 구현 착수용 초안**  
대상은 광고 운영자가 Windows 브라우저에서 사용하는 기존 GitHub Pages 대시보드다. 이번 문서의 산출물은 작업 범위와 인수 기준이다. 아래 브랜치명과 화면 문구는 구현 시 사용할 제안이다.

**완료 조건** — 운영자가 거래처 표 한 장을 가져와 애매한 열만 확인한 뒤, 소재 한 건의 등급이 어떤 목표와 실적으로 결정됐는지 화면에서 설명할 수 있어야 한다. 다음 달에 같은 양식을 받으면 기존 연결을 재사용할 수 있어야 한다.

## 1. 범위와 원본 보호

- 입력 경로는 ① 로컬 엑셀 파일(.xlsx) 선택과 ② 엑셀·구글시트에서 복사한 셀 범위 붙여넣기다. 기존 수기 입력·수정, 프로젝트 전환·저장, 샘플 보기도 유지한다.
- 파일·클립보드 해석, 열 연결, 계산, 설정 저장은 브라우저에서 수행한다. 외부 API, Google 로그인·시트 URL 동기화, AI 호출, 캡처·OCR, Windows 설치형 앱은 이번 범위에서 제외한다. 원본 파일과 셀 값의 처리 범위는 사용자 브라우저 안이다.
- 검토한 기준 커밋은 [0db6ece](https://github.com/dpes31/media-insight/tree/0db6ece8bfbcc47491d788659661d1c20b9537e6)다. 착수 시 최신 main과 차이를 확인하고 출발 커밋 SHA를 PR에 기록한다. 그 커밋에서 test/report-import-v1 브랜치를 만들어 작업한다.
- 테스트는 로컬 또는 별도 출처(origin)의 미리보기에서 진행한다. 같은 호스트의 다른 경로에서는 localStorage를 공유하므로 운영 주소에서 가져오기·저장 시험을 하지 않는다. 실거래처 파일은 저장소에 올리지 않고 익명화한 예제만 사용한다.

## 2. 구현 순서와 단계별 산출물

| 순서 | 작업 | 다음 단계로 넘어갈 조건 |
|---|---|---|
| 1 | 기존 샘플 결과와 저장 형식을 기록한다. 기존 프로젝트 생성·복원·수기 분석을 확인하고, 중복 프로젝트명으로 기존 데이터가 덮이는 문제를 수정한다. | 동일 이름으로 생성을 시도한 후 새로고침해도 기존 값이 남는다. |
| 2 | 한국어 제목, 복수 시트, 백분율 셀, 소계 행을 포함한 예제를 만든다. 업체 양식 확보 전에는 가상 자료로 시작하고, 확보한 익명 양식으로 지원 범위를 확인한다. | 각 예제의 예상 연결, 제외 행, 합계와 지표를 손으로 검산한 표가 있다. |
| 3 | 엑셀과 붙여넣기 입력을 공통 행 형식으로 변환한다. 미리보기·열 연결·단위 확인·반영을 한 흐름으로 구현한다. | 두 입력 경로로 같은 자료를 읽으면 같은 행과 같은 수치가 나온다. |
| 4 | 업체별 열 연결 기억, 재가져오기, 매체 목표 적용, 소재별 근거 표시 및 분석 기준 미리보기를 구현한다. | 행 중복 없이 갱신할 수 있고, 기준 수정으로 등급이 바뀌는 이유를 설명할 수 있다. |
| 5 | 아래 인수 테스트와 Windows 브라우저 검수를 수행하고 PR을 작성한다. | 검증 결과와 의도한 결과 차이를 보고 사용자가 main 병합을 결정할 수 있다. |

기존 HTML·JavaScript·Tailwind를 활용한다. 입력 해석, 채점·집계, 프로젝트 저장, 화면 표시를 독립적으로 검증할 수 있게 분리한다. 엑셀 해석 라이브러리는 버전과 라이선스를 기록해 정적 사이트와 함께 제공한다. 배포 후 사용자에게 필요한 것은 브라우저뿐이다.

## 3. 자료 가져오기 동작

1. **자료 선택.** 사용자가 프로젝트·대상 기간과 자료 성격(계획 또는 실적)을 확인한다. 엑셀은 시트·제목 행·데이터 범위를 선택하고, 붙여넣기는 탭과 줄바꿈으로 구분된 셀 범위를 같은 미리보기로 연다. 다단·병합 제목은 상위 제목을 함께 표시한다. 숫자값이 없는 수식 셀은 확인 대상으로 남긴다.
2. **열 연결.** 제목과 단위로 항목을 찾는다. 예를 들어 ‘소진금액’은 광고비, ‘예상 CPC’는 목표 CPC로 제안한다. ‘단가’, 중복 제목, 계획·실적이 한 표에 섞인 경우는 원본 제목과 예시 값을 보여주고 사용자가 결정한다. 사용자가 열을 제외하거나 제안을 고칠 수 있어야 한다.
3. **목표 연결.** 목표는 소재별 명시값을 우선하고, 없으면 같은 프로젝트·기간·매체 및 해당 상품 범위의 계획 목표를 제안한다. 매체 전체 목표를 여러 소재에 적용할 때는 출처를 표시한다. 예산과 예상 클릭으로 CPC를 역산할 수 있지만, 명시 목표와 다르면 두 값을 제시한다. 매체 전체 예산이나 노출 계획을 소재마다 복제해 합산하지 않는다.
4. **단위 확인.** 금액의 원/천원, 비율의 소수/퍼센트를 구분한다. 예컨대 엑셀의 백분율 셀 0.01과 붙여넣기의 ‘1%’는 같은 값이다. 숫자만 있는 ‘1’은 단위를 확인한다. 빈칸·계산 불가·실제 0을 구별하고 단위 변환 결과를 미리 보여준다.
5. **반영.** 빈 줄, 소계·합계 후보, 인식 오류를 표시한다. 추가·갱신·제외할 행 수를 먼저 보여주고 확정 시 한 번에 저장한다. 취소나 읽기·저장 실패 시 이전 프로젝트를 복원할 수 있어야 한다. 동일 자료 재반영은 합계를 유지한다. 집계 행의 기본 식별 후보는 프로젝트·기간·매체·상품·소재다. 같은 조합이 복수이거나 기간이 겹쳐 갱신 대상을 특정할 수 없으면 사용자에게 확인한다.
6. **양식 기억.** 업체별로 원본 열 제목·상위 제목·단위와 분석 항목의 연결을 저장한다. 열을 재배열해도 제목으로 찾고, 새 열·변경된 단위·없어진 필수 열만 다시 확인한다. 인식한 셀 문자열은 화면에서 일반 텍스트로 표시한다.

## 4. 분석 기준과 화면 설계

**업체 양식과 캠페인 기준을 분리한다.** 업체 양식은 어느 열을 읽을지 결정한다. 캠페인 기준은 어떤 목표값과 임계값으로 평가할지 결정한다. 초기 기본값은 현행 채점 기준을 사용하고, 사용자 설정은 프로젝트별로 저장한다. 기준 변경 시 같은 입력으로 변경 전후 등급·점수·변경 소재 수를 미리 보여준다. 적용 후 결과 상세에 기준 이름·버전, 실제 적용한 목표값, 목표 출처를 표시한다. 취소하면 원래 결과를 유지한다.

**화면의 중심은 소재 비교표다.** 빈 프로젝트의 첫 행동은 ‘자료 가져오기’, 샘플 보기는 보조 동작으로 둔다. 자료가 들어오면 프로젝트·기간·출처·반영 시각과 확인이 필요한 행을 상단에 표시한다. 소재 행을 선택하면 목표, 실적, 계산식, 등급의 이유를 펼친다. 4분면은 전체 분포를 볼 때 여는 보조 보기로 둔다. 첨부한 Stageshow 예시에서는 실제 제품 동작을 짧게 보여주는 방식을 참고한다. 소개용 모션이나 React 전환은 이번 구현의 전제 조건이 아니다.

**의도한 계산·표시 변경을 명시한다.** 정상 입력의 기존 지표와 기본 채점은 유지한다. DA 등급과 전환 평가는 각각 표시한다. 전환 0건이면 CVR은 클릭이 있을 때 0%, CPA는 산출 불가다. 전환 미입력은 미입력으로 표시한다. 매출 미입력은 ROAS 산출 불가, 매출 0원이고 광고비가 양수면 ROAS 0%다. 전체 비율은 합산된 분자와 분모로 계산한다. 일부 행에 전환이나 매출이 빠지면 해당 지표에 누락 범위를 표시해 전체 확정값으로 오인하지 않도록 한다.

## 5. 인수 테스트

기준 행은 광고비 100,000원, 노출 10,000회, 클릭 100회, 전환 5건, 매출 300,000원이다.

| 검사 | 통과 조건 |
|---|---|
| 기본 수치 | CPM 10,000원, CPC 1,000원, CTR 1%, CVR 5%, CPA 20,000원, ROAS 300%. 수기·엑셀·붙여넣기와 열 순서 변경에서 동일하다. |
| 가중 집계 | 기준 행에 광고비 20,000원·노출 1,000·클릭 20 행을 더하면 전체 CTR은 120 ÷ 11,000 ≈ 1.09%다. 소계 행을 포함해 가져와도 결과가 같다. |
| 결측·0 | 전환 0·전환 공란·매출 0·매출 공란을 각각 검증한다. 클릭 또는 광고비가 0인 경우도 해당 분모로 나누는 지표에 산출 불가를 표시한다. |
| 의미·단위 | 열 이름 ‘단가’와 숫자만 있는 비율은 확인 대상으로 남는다. 원/천원, 1%/엑셀 백분율 셀 변환 후 수치가 일치한다. |
| 계획 연결 | 매체 목표 1건과 소재 실적 2건을 연결한다. 두 소재에 목표 출처가 보이고 합계는 실적만 한 번씩 더한다. |
| 재반영·취소 | 같은 표를 두 번 넣어도 총액이 같다. 한 행의 실적만 수정해 갱신하면 그 차액만 변한다. 미리보기 취소·잘못된 파일·저장 실패 후 기존 값이 유지된다. |
| 설정 적용 | 경계값 직전·경계값·직후의 점수를 검사한다. 설정 미리보기와 적용 결과가 일치하고 새로고침 후에도 해당 프로젝트에만 유지된다. |
| 기존 사용자 | 기존 저장 형식의 프로젝트를 불러와 수기 수정·저장·전환이 가능하다. 같은 이름으로 새 프로젝트를 만들어도 이전 데이터가 유지된다. |
| 배포 검수 | Windows Edge 또는 Chrome에서 파일 선택부터 근거 확인까지 수행한다. 네트워크 기록에서 가져온 셀·파일의 외부 전송이 없음을 확인한다. |

## 6. PR과 병합 판단

PR에는 출발 SHA, 익명 예제와 예상값, 테스트별 실제 결과, 기존 버전 대비 바뀐 계산·표시, 저장 호환성 검증 결과를 첨부한다. 화면 증빙은 ‘가져오기 미리보기’와 ‘소재 판단 근거’를 중심으로 남긴다. 실제 업체 양식과 Windows 환경에서 확인한 항목 및 미검증 항목을 구분한다.

병합 전에는 기존 저장 데이터 사본으로 새 버전 로드와 복원 절차를 확인한다. 저장 형식을 변경하면 버전 식별과 이전 값 복구 방법을 함께 제공한다. 운영 배포 후 문제가 발견되면 병합 커밋을 되돌리고 필요 시 보관한 이전 형식의 데이터를 복구한다. 테스트 브랜치 작업의 종료점은 검증 결과가 첨부된 PR이며, 운영 반영은 사용자 검토 후 결정한다.
